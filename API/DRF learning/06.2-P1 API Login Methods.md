# 06.2 - API Login Methods (Part 1)

## اهداف فصل

در پایان این فصل:

* تفاوت روش‌های Login در DRF را درک می‌کنید.
* با Session Authentication آشنا می‌شوید.
* کاربرد `api-auth/` را می‌شناسید.
* نقش `dj-rest-auth` را در پروژه‌های واقعی درک می‌کنید.
* با `django-allauth` آشنا می‌شوید.
* می‌دانید هر روش در چه سناریویی مناسب است.
* برای ادامه فصل JWT (Simple JWT) آماده خواهید شد.

---

# مقدمه

بعد از یادگیری Authentication و Permission معمولاً اولین سؤال این است:

> «کاربر چگونه وارد سیستم (Login) شود؟»

بسیاری از توسعه‌دهندگان تازه‌کار تصور می‌کنند DRF فقط یک روش برای Login دارد، در حالی که بسته به نوع پروژه، چندین راهکار مختلف وجود دارد.

هر روش برای یک سناریوی خاص طراحی شده است و انتخاب صحیح آن، سادگی توسعه و امنیت سامانه را افزایش می‌دهد.

---

# قبل از شروع

ابتدا باید تفاوت دو مفهوم را بدانیم.

Authentication پاسخ می‌دهد:

```text
این کاربر چه کسی است؟
```

اما Login پاسخ می‌دهد:

```text
کاربر چگونه هویت خود را به سیستم اثبات کند؟
```

به عبارت دیگر:

```text
Login
        ↓
Authentication
        ↓
Permission
        ↓
Access API
```

بنابراین Login بخشی از فرآیند Authentication است، نه جایگزین آن.

---

# روش‌های متداول Login در DRF

در اکوسیستم Django و DRF چهار روش رایج وجود دارد.

---

## روش اول

### Session Authentication

در این روش پس از ورود کاربر، Django یک Session ایجاد می‌کند.

مرورگر نیز شناسه Session را در Cookie ذخیره می‌کند و در درخواست‌های بعدی همان Cookie ارسال می‌شود.

این همان روشی است که پنل مدیریت Django نیز از آن استفاده می‌کند.

---

مزایا

* پیاده‌سازی ساده
* امنیت بالا در برنامه‌های مبتنی بر Django
* مناسب برای وب‌سایت‌های سنتی

---

محدودیت

برای برنامه‌های موبایل یا SPA معمولاً انتخاب مناسبی نیست.

---

# روش دوم

## Browsable API Login

یکی از امکانات جذاب DRF رابط کاربری Browsable API است.

اگر مسیر زیر را اضافه کنید:

فایل:

```text
MyProject/config/urls.py
```

```python
from django.urls import include, path

urlpatterns = [
    path(
        "api-auth/",
        include("rest_framework.urls"),
    ),
]
```

DRF صفحات Login و Logout را در اختیار شما قرار می‌دهد.

---

پس از ورود:

* Session ایجاد می‌شود.
* مرورگر Cookie را نگهداری می‌کند.
* تمام درخواست‌های بعدی با همان Session ارسال می‌شوند.

---

این قابلیت برای موارد زیر بسیار مناسب است:

* توسعه API
* تست Endpointها
* آموزش
* بررسی Permissionها

---

اما برای Frontendهای مستقل یا Mobile استفاده نمی‌شود.

---

# روش سوم

## dj-rest-auth

وقتی پروژه بزرگ‌تر می‌شود، فقط داشتن صفحه Login کافی نیست.

معمولاً به امکانات زیر نیاز داریم:

* Login API
* Logout API
* Register API
* Change Password
* Reset Password
* Current User API
* Email Verification

پیاده‌سازی همه این امکانات از ابتدا زمان‌بر و مستعد خطاست.

برای همین کتابخانه **dj-rest-auth** ایجاد شده است.

این کتابخانه مجموعه‌ای از Endpointهای آماده برای احراز هویت کاربران در اختیار شما قرار می‌دهد و به‌صورت کامل با Django و DRF یکپارچه است.

---

# روش چهارم

## django-allauth

خود **dj-rest-auth** مسئول مدیریت حساب کاربری نیست.

برای امکاناتی مانند:

* ثبت‌نام کاربران
* تأیید ایمیل
* تغییر ایمیل
* ورود با Google
* ورود با GitHub
* ورود با Microsoft

از **django-allauth** استفاده می‌کند.

به همین دلیل در اکثر پروژه‌ها این دو کتابخانه در کنار یکدیگر نصب می‌شوند.

---

# ارتباط این سه ابزار

بهترین روش برای درک آن‌ها، نگاه کردن به مسئولیت هر کدام است.

| ابزار     | مسئولیت                                         |
| -------------- | ------------------------------------------------------ |
| Django         | مدیریت کاربران و Session                 |
| DRF            | Authentication و Permission برای API              |
| dj-rest-auth   | ارائه Endpointهای آماده Login و Logout   |
| django-allauth | ثبت‌نام، تأیید ایمیل و Social Login |

به همین دلیل نصب هم‌زمان آن‌ها کاملاً طبیعی است.

---

# چه زمانی از هر کدام استفاده کنیم؟

| نوع پروژه                               | پیشنهاد                      |
| ----------------------------------------------- | ----------------------------------- |
| آموزش DRF                                  | `api-auth/`                       |
| تست Browsable API                            | `api-auth/`                       |
| وب‌سایت Django                           | Session Authentication              |
| API برای React                              | `dj-rest-auth`+ JWT               |
| API برای Flutter                            | `dj-rest-auth`+ JWT               |
| سامانه با ثبت‌نام کاربران | `dj-rest-auth`+`django-allauth` |
| Social Login                                    | `django-allauth`                  |

---

# مسیر ادامه فصل

در بخش بعدی به‌صورت عملی خواهیم دید:

1. چگونه `api-auth/` را فعال کنیم.
2. این مسیر دقیقاً چه کاری انجام می‌دهد.
3. Login و Logout چگونه کار می‌کنند.
4. Session چگونه ایجاد می‌شود.
5. چه تفاوتی با JWT دارد.

در انتهای فصل نیز `dj-rest-auth` و `django-allauth` را به‌صورت کامل پیکربندی خواهیم کرد و ارتباط آن‌ها با فصل **JWT Authentication (Simple JWT)** را بررسی خواهیم کرد.
