
# 06.2 - dj-rest-auth & django-allauth (Part 3)

## اولین APIهای آماده

بعد از اضافه کردن:

فایل:

```text
MyProject/config/urls.py
```

```python
urlpatterns = [

    path(
        "api/auth/",
        include("dj_rest_auth.urls"),
    ),

    path(
        "api/auth/registration/",
        include(
            "dj_rest_auth.registration.urls"
        ),
    ),
]
```

مجموعه‌ای از Endpointهای استاندارد در اختیار شما قرار می‌گیرد.

مزیت اصلی این کتابخانه این است که بدون نوشتن View اختصاصی، عملیات متداول احراز هویت را انجام می‌دهد.

---

# Login

آدرس:

```http
POST /api/auth/login/
```

وظیفه:

احراز هویت کاربر و ایجاد Session یا Token (بسته به تنظیمات پروژه).

---

نمونه Request

```json
{
    "username": "sajad",
    "password": "StrongPassword123"
}
```

---

نمونه Response

در حالت Session Authentication:

```json
{
    "detail": "Successfully logged in."
}
```

اگر از JWT استفاده شود (در ادامه فصل):

```json
{
    "access": "...",
    "refresh": "..."
}
```

---

# Logout

آدرس

```http
POST /api/auth/logout/
```

---

وظیفه

خاتمه دادن به Session یا بی‌اعتبار کردن Token (بسته به نوع Authentication).

---

نمونه Response

```json
{
    "detail": "Successfully logged out."
}
```

---

# Current User

آدرس

```http
GET /api/auth/user/
```

---

این Endpoint اطلاعات کاربر فعلی را برمی‌گرداند.

نمونه:

```json
{
    "pk": 1,
    "username": "sajad",
    "email": "user@example.com"
}
```

---

مزیت

تقریباً تمام Frontendها پس از Login ابتدا این Endpoint را فراخوانی می‌کنند.

---

# Change Password

آدرس

```http
POST /api/auth/password/change/
```

---

نمونه Request

```json
{
    "new_password1": "NewPassword123",
    "new_password2": "NewPassword123"
}
```

---

این Endpoint فقط برای کاربران احراز هویت‌شده قابل استفاده است.

---

# Password Reset

اگر کاربر رمز عبور خود را فراموش کند.

آدرس

```http
POST /api/auth/password/reset/
```

---

نمونه Request

```json
{
    "email": "user@example.com"
}
```

---

در صورت تنظیم صحیح Email Backend، لینک بازیابی رمز عبور برای کاربر ارسال خواهد شد.

---

# Password Reset Confirm

پس از کلیک روی لینک ارسال‌شده در ایمیل، Frontend اطلاعات زیر را ارسال می‌کند.

```http
POST /api/auth/password/reset/confirm/
```

---

نمونه Request

```json
{
    "uid": "...",
    "token": "...",
    "new_password1": "...",
    "new_password2": "..."
}
```

---

# Register

این Endpoint توسط:

```text
dj_rest_auth.registration
```

اضافه می‌شود.

---

آدرس

```http
POST /api/auth/registration/
```

---

نمونه Request

```json
{
    "username": "newuser",
    "email": "new@example.com",
    "password1": "StrongPassword123",
    "password2": "StrongPassword123"
}
```

---

پس از موفقیت:

* کاربر ایجاد می‌شود.
* در صورت فعال بودن تأیید ایمیل، ایمیل فعال‌سازی ارسال می‌شود.

---

# Verify Email

اگر تأیید ایمیل فعال باشد، کاربر باید ایمیل خود را تأیید کند.

این قابلیت توسط:

```text
django-allauth
```

مدیریت می‌شود.

---

# Resend Verification Email

در صورت عدم دریافت ایمیل:

کاربر می‌تواند درخواست ارسال مجدد بدهد.

# معماری کلی Endpointها

```text
                Login
                  │
                  ▼
        Authentication
                  │
        ┌─────────┴─────────┐
        ▼                   ▼
Current User          Change Password
        │
        ▼
Logout

Registration
        │
        ▼
Verify Email
```

---

# نکته مهم

همه Endpointهای فوق مستقیماً از:

* Viewهای استاندارد
* Serializerهای استاندارد
* Validationهای استاندارد

کتابخانه استفاده می‌کنند.

به همین دلیل تا زمانی که نیاز خاصی ندارید، نیازی به بازنویسی آن‌ها نیست.

---

# آیا باید View اختصاصی بنویسیم؟

در اکثر پروژه‌ها:

**خیر.**

کتابخانه تقریباً تمام نیازهای متداول را پوشش می‌دهد.

تنها زمانی View اختصاصی می‌نویسیم که:

* منطق ثبت‌نام اختصاصی باشد.
* اطلاعات بیشتری هنگام ثبت‌نام دریافت شود.
* قوانین امنیتی خاصی وجود داشته باشد.
* فرآیند احراز هویت سفارشی باشد.

---

# اشتباه رایج

بسیاری از توسعه‌دهندگان پس از نصب `dj-rest-auth` بلافاصله Viewهای Login و Register اختصاصی می‌نویسند.

در بیشتر پروژه‌ها این کار ضرورتی ندارد و فقط باعث افزایش حجم کد و هزینه نگهداری می‌شود.

ابتدا از Endpointهای استاندارد استفاده کنید و تنها در صورت وجود نیاز واقعی آن‌ها را سفارشی‌سازی کنید.
