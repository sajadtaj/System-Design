
# 06.2 - dj-rest-auth & django-allauth (Part 2)

## اهداف فصل

در پایان این بخش:

* با کتابخانه **dj-rest-auth** آشنا می‌شوید.
* نقش **django-allauth** را در احراز هویت درک می‌کنید.
* تفاوت مسئولیت این دو کتابخانه را می‌دانید.
* آن‌ها را به‌صورت صحیح در پروژه نصب و پیکربندی می‌کنید.
* برای ساخت APIهای Login و Register آماده خواهید شد.

---

# چرا به dj-rest-auth نیاز داریم؟

فرض کنید بخواهیم امکانات زیر را برای کاربران پیاده‌سازی کنیم:

* Login
* Logout
* Register
* Change Password
* Reset Password
* Verify Email
* Current User

پیاده‌سازی همه این Endpointها از ابتدا زمان‌بر و مستعد خطاست.

کتابخانه **dj-rest-auth** این قابلیت‌ها را به‌صورت آماده و هماهنگ با Django و DRF در اختیار ما قرار می‌دهد.

---

# نقش django-allauth

در اینجا معمولاً یک سوءبرداشت وجود دارد.

بسیاری تصور می‌کنند:

```text
dj-rest-auth
```

ثبت‌نام کاربران را انجام می‌دهد.

در حالی که در واقع:

```text
dj-rest-auth
```

فقط APIهای لازم را فراهم می‌کند.

اما منطق مربوط به:

* ثبت‌نام
* تأیید ایمیل
* مدیریت حساب کاربری
* ورود با سرویس‌های اجتماعی

بر عهده:

```text
django-allauth
```

است.

# افزودن به INSTALLED_APPS

فایل:

```text
MyProject/config/settings.py
```

```python
INSTALLED_APPS = [

    ...

    "django.contrib.sites",

    "rest_framework",

    "dj_rest_auth",

    "allauth",

    "allauth.account",

    "allauth.socialaccount",

]
```

---

اگر قصد دارید امکان ثبت‌نام کاربران را نیز فعال کنید:

```python
INSTALLED_APPS += [

    "dj_rest_auth.registration",

]
```

---

# نقش هر App

| App                           | وظیفه                                                           |
| ----------------------------- | -------------------------------------------------------------------- |
| `dj_rest_auth`              | Login، Logout، Password Management                                 |
| `dj_rest_auth.registration` | API ثبت‌نام                                                   |
| `allauth`                   | هسته مدیریت حساب                                       |
| `allauth.account`           | ثبت‌نام و مدیریت حساب                              |
| `allauth.socialaccount`     | ورود با Google، GitHub و سایر ارائه‌دهندگان |

# تنظیم SITE_ID

از آنجا که `django-allauth` از فریم‌ورک Sites استفاده می‌کند، باید مقدار `SITE_ID` را نیز مشخص کنید.

فایل:

```text
MyProject/config/settings.py
```

```python
SITE_ID = 1
```

در محیط‌های چندسایتی، هر سایت شناسه مخصوص به خود را خواهد داشت.

---

# افزودن URLها

فایل:

```text
MyProject/config/urls.py
```

```python
from django.urls import include, path

urlpatterns = [

    ...

    path(
        "api/auth/",
        include("dj_rest_auth.urls"),
    ),

]
```

---

اگر ثبت‌نام کاربران نیز فعال باشد:

```python
urlpatterns += [

    path(
        "api/auth/registration/",
        include(
            "dj_rest_auth.registration.urls"
        ),
    ),

]
```

---

در این مرحله، بدون نوشتن حتی یک View اختصاصی، مجموعه‌ای از Endpointهای استاندارد برای احراز هویت در اختیار خواهید داشت.

# نکات مهم

* `dj-rest-auth` جایگزین سیستم احراز هویت Django نیست؛ بلکه یک لایه REST روی آن ایجاد می‌کند.
* برای قابلیت‌های ثبت‌نام و تأیید ایمیل، وجود `django-allauth` ضروری است.
* اگر فقط به Login و Logout نیاز دارید، می‌توانید فقط `dj_rest_auth` را نصب کنید.
* اگر Registration را فعال می‌کنید، باید `dj_rest_auth.registration` و `django-allauth` را نیز اضافه کنید.
