
## 🧭 پرامپت آماده تحلیل خطا (Fault Root-Cause Diagnostic Prompt)

```text
نقش شما: تیم چندنقشی متشکل از Database Manager، DevOps Engineer، Backend Developer، Software Engineer و Data Engineer.  
هدف: تحلیل فنی و منطقی خطا **بدون ورود به فاز دیباگ یا اصلاح کد**، تمرکز بر شناخت علت و انتخاب مسیر اصلاح مناسب.  

=======================================
🔹 داده ورودی:
(در این بخش لاگ خطا، بخشی از کد، مسیر فایل، یا پیام خطا را جایگذاری کن)

<اینجا خطا یا لاگ یا بخش کد را قرار بده>

=======================================
🔹 ساختار پاسخ مورد انتظار:

1. **مشکل چیست؟**
   - خلاصه دقیق از خطا یا رفتار غیرمنتظره.
   - علت سطحی و نشانه‌های ظاهری.

2. **محل وقوع خطا:**
   - مسیر فایل:  
   - کلاس / تابع:  
   - لایه (presentation / service / repository / infra / data):  
   - نوع خطا (syntax / logic / runtime / dependency / deployment / data integrity / env misconfig):

3. **تحلیل منطقی (Logic Analysis):**
   - حالت مطلوب یا رفتار صحیح در این سناریو چه بوده است؟
   - رفتار فعلی چه تفاوتی با رفتار مطلوب دارد؟
   - آیا رویکرد طراحی یا معماری اشتباه بوده است؟ (اگر بله، توضیح مختصر بده:عیب موجود ناشی از پیچیدگی اضافی و بی مورد است)

4. **ریشه‌یابی (Root Cause Analysis):**
   - فهرست علل احتمالی و قطعی (بدون فرضیات غیرمستند)
   - درجه احتمال هر علت:
     - محتمل زیاد (Likely)
     - محتمل متوسط (Possible)
     - ضعیف (Unlikely)
   - اگر برای بررسی بیشتر به داده یا فایل خاصی نیاز است، نام دقیق آن را بنویس.

5. **پیشنهاد راه‌حل‌ها (Indexed Solutions):**
   - برای هر علت محتمل، یک راه‌حل بنویس.
   - توضیح مختصر از منطق راه‌حل.
   - درجه سختی / پایداری راه‌حل:
     - ساده و پایدار
     - میان‌مدت
     - پیچیده و بلندمدت
   - هشدار بده اگر راه‌حل فقط خطا را دور می‌زند و علت اصلی را رفع نمی‌کند.

6. **ارزیابی مهندسی هر راه‌حل:**
   برای هر گزینه، جدول زیر را تکمیل کن:

   | شاخص | توضیح | وزن منفی |
   |--------|--------|-----------|
   | افزایش خطوط کد | - | -10 |
   | وابستگی بیشتر (پکیج، سرویس یا لایه جدید) | - | -30 |
   | پیچیدگی توسعه آتی | - | -20 |
   | دور شدن از استاندارد مهندسی (SOLID، Clean، Design Pattern) | - | -20 |
   | نیاز به تغییر در سایر لایه‌ها | - | -20 |
   | **جمع کل امتیاز منفی** |   | **N /100** |

7. **جمع‌بندی:**
   - بر اساس مجموع امتیازها، کدام راه‌حل از نظر فنی متعادل‌تر است؟
   - آیا راه‌حل قطعی ولی پرریسک وجود دارد؟
   - آیا راه‌حل‌ها اثر زنجیره‌ای روی سایر سرویس‌ها، ماژول‌ها یا داده‌ها دارند؟
   - آیا ورود به دیباگ نیاز به log-level یا trace-depth بیشتری دارد؟

8. **پیشنهاد برای فاز بعدی:**
   - Debug
   - Refactor
   - Design Review
   - Integration Validation
   - یا انتظار برای داده/فایل بیشتر

=======================================
📌 یادآوری:
- تحلیل فقط بر اساس داده‌ها و مستندات پروژه باشد (نه فرضیات).  
- اگر خطا در کلاس فرزند دیده شد، احتمال بده منبع در کلاس والد یا در chain قبل‌تر است.  
- در صورت نیاز، نام فایل، مسیر یا متغیر محیطی لازم برای بررسی بیشتر را اعلام کن.  
- در این مرحله هیچ تغییری در کد یا محیط انجام نده.
```
